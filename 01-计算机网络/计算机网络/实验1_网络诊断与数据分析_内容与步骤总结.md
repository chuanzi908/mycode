## 一、实验定位

这是一份**三层递进式**的综合实验：先用命令行把网络"看透"，再用 Python 把数据"算清"，最后用 AI 把诊断"自动化"。技术栈从 **运维命令 → 数据分析 → 智能体（AIOps）** 逐级上升。

```
命令层（采集与验证）  →  数据层（结构化与可视化）  →  智能层（Agent 自动诊断）
   ipconfig/ping/...        Python + 正则 + matplotlib        大模型 + 工具调用
```

## 二、实验目的（原文 5 条）

1. 熟练掌握 Windows 环境下 `ipconfig`、`ping`、`tracert`、`netstat`、`arp`、`route`、`netsh` 等命令的功能、格式和典型应用场景。
2. 通过**分层排查法**（本地环回 → 本机 IP → 网关 → 外网），建立系统化的网络故障排查思路。
3. 了解智能体（Agent）的基本工作原理（感知–思考–行动–反馈），并亲手搭建一个能执行网络命令的 AI 助手。
4. 将命令行收集到的网络数据，通过 Python 进行结构化处理、统计分析和可视化，初步具备"数据驱动"的网络诊断思维。
5. 学习将传统命令行工具封装为 AI 可调用的"工具"（Tool），理解 AI 与自动化运维（AIOps）的结合方式。

## 四、实验内容（原文三大模块）

### （一）网络命令操作（6 项）

1. 用 `ipconfig` 查看 IP/MAC/DNS 信息及刷新 DNS 缓存；用 `netsh` 完成**静态 IP 与 DHCP 动态获取的切换**，并编写自动化批处理脚本。
2. 用 `ping` 从**本地协议栈、网卡、网关、互联网到 DNS 解析**做五层连通性验证，理解 TTL、数据包分片等参数含义。
3. 用 `tracert` 追踪数据包传输路径，分析路由跳数、节点延迟及超时现象，对比不同参数对追踪效率的影响。
4. 用 `netstat` 查看 TCP/UDP 端口监听与活动连接，关联进程 PID，掌握特定端口占用情况的排查方法。
5. 观察 **ARP 缓存表**的动态学习过程，验证 ARP 请求与响应在局域网通信中的作用，掌握缓存清除操作。
6. 查看系统 **IPv4 路由表**，掌握静态路由的添加、验证与删除，理解默认网关与特定网段路由的优先级。

### （二）基于 Python 的网络数据分析（5 项）

1. 用 Windows 命令行执行**大规模 Ping 探测和路由追踪**，把非结构化文本输出重定向保存为本地数据文件，建立原始数据集。
2. 编写 Python 脚本读取 Ping 日志，用**正则表达式**精准提取每次探测的往返时延（RTT），转为数值型列表，完成结构化处理。
3. 用统计学方法计算延迟数据的**均值、标准差、极值**等指标；基于"**均值 + 2 倍标准差**"原则定义动态异常阈值，自动识别网络抖动或高延迟的异常探测点。
4. 用 **Matplotlib**（或其他绘图库）绘制延迟**时序折线图**与**分布直方图**，展示延迟随时间的变化趋势与整体分布特征，并在图中标记异常点。
5. 解析 **Tracert 日志**，提取每一跳的路由节点 IP 及响应延迟；统计总跳数，识别路径中的高延迟瓶颈节点，并以结构化表格输出路由分析报告。

### （三）AI 赋能网络诊断（任选一种方案）（4 项）

1. 创建专属"**网络诊断助手**"智能体：添加 HTTP 请求插件、内置代码节点实现本地网络命令调用，配置标准化网络排查逻辑，完成故障场景测试并发布上线。
2. 使用大语言模型，通过**直接对话调用**、**自定义函数配置**两种方式，实现网络命令自动执行与诊断报告自动生成，覆盖**正常网络、断网**两种场景完成结果校验。
3. 使用大语言模型，赋予智能体**系统命令执行权限**，配置"资深网络运维专家"角色提示词，验证智能体自主规划排查步骤、输出诊断结论的全流程能力。
4. 使用大语言模型，开发可自动访问**在线网络诊断工具**的自定义插件，实现指定目标网站的跨节点网络状态自动探测与结果返回。

## 五、具体实验步骤（按内容补全）

> 以下命令均在 **Windows 命令提示符（CMD）** 中执行；涉及 `netsh`、`route`、`arp -s` 等修改系统配置的命令，需**以管理员身份运行**，实验完成后务必恢复原状。

### 模块一 网络命令操作

**步骤 1　ipconfig：查看本机网络参数**

```cmd
ipconfig /all                     :: 查看 IP、子网掩码、网关、MAC、DNS、DHCP 状态
ipconfig /displaydns              :: 查看本机 DNS 缓存记录
ipconfig /flushdns                :: 刷新（清空）DNS 缓存
ipconfig /release                 :: 释放当前 DHCP 地址
ipconfig /renew                   :: 重新申请 IP 地址
```
记录要点：IPv4 地址、默认网关、物理地址（MAC）、DNS 服务器。

**步骤 2　netsh：静态 IP / DHCP 切换 + 批处理脚本**

```cmd
netsh interface ip show config                                  :: 查看接口当前配置
netsh interface ip set address "以太网" static 192.168.1.100 255.255.255.0 192.168.1.1
netsh interface ip set dns "以太网" static 8.8.8.8
netsh interface ip set address "以太网" dhcp                    :: 恢复 DHCP
netsh interface ip set dns "以太网" dhcp
```
把两条命令分别写成 `set_static.bat` / `set_dhcp.bat`，双击即完成切换，再用 `ipconfig` 验证结果。
> 注意：接口名以 `netsh interface ip show interfaces` 输出为准（可能是"以太网""WLAN"等）。

**步骤 3　ping：五层连通性验证（分层排查法核心）**

```cmd
ping 127.0.0.1            :: ① 本地环回：验证 TCP/IP 协议栈
ping <本机IP>             :: ② 本机网卡是否正常工作
ping <默认网关>           :: ③ 到网关（局域网出口）是否通
ping 8.8.8.8              :: ④ 到外网 IP 是否通（排除 DNS 因素）
ping www.baidu.com        :: ⑤ 域名解析是否正常（验证 DNS）
```
参数对比实验：
```cmd
ping -n 10 8.8.8.8        :: 指定探测次数
ping -l 1500 -f 8.8.8.8   :: 1500 字节载荷 + 禁止分片，观察分片/超时现象
ping -w 2000 www.baidu.com :: 设置等待超时（ms）
ping -t 8.8.8.8           :: 持续 ping，Ctrl+C 停止（看丢包率）
```
记录每次的**往返时间、TTL、丢包率**，并说明 TTL 如何推断目标系统类型。

**步骤 4　tracert：路径追踪与参数对比**

```cmd
tracert www.baidu.com
tracert -d -h 15 -w 1000 www.baidu.com   :: -d 不解析域名(更快) -h 最大跳数 -w 超时
```
对比加不加 `-d` 的耗时差异；记录每一跳的 IP、延迟；解释出现 `*` 超时的原因（节点屏蔽 ICMP）。

**步骤 5　netstat：端口与连接排查**

```cmd
netstat -ano                       :: 所有连接/监听端口 + 进程 PID
netstat -ano | findstr :80         :: 排查 80 端口占用
netstat -ano | findstr LISTENING   :: 只看监听状态的端口
tasklist | findstr <PID>           :: 由 PID 反查进程名
netstat -s                         :: 分协议统计（TCP/UDP/ICMP）
```
要求：找出一个被占用端口，说明是哪个进程占用。

**步骤 6　arp：缓存动态学习与清除**

```cmd
arp -a                    :: 查看 ARP 缓存表
arp -d                    :: 清除（删除）ARP 缓存
ping <同网段主机或网关>    :: 触发一次通信
arp -a                    :: 再次查看，观察缓存中新增/更新的条目
arp -s <IP> <MAC>         :: 静态绑定（实验后可用 arp -d 删除）
```
结论：ARP 请求是广播、响应是单播，缓存条目有动态学习与老化机制。

**步骤 7　route：路由表查看与静态路由管理**

```cmd
route print                                   :: 查看 IPv4 路由表（重点看 0.0.0.0 默认路由）
route add 10.10.0.0 mask 255.255.0.0 192.168.1.1   :: 添加静态路由
route print                                   :: 验证路由是否生效
route delete 10.10.0.0                        :: 删除该路由
route -p add ...                              :: 加 -p 表示永久路由（重启保留）
```
结合"最长前缀匹配 + 跃点数"解释：为什么访问外网走默认网关，而访问特定网段走专线路由。

### 模块二 基于 Python 的网络数据分析

**步骤 1　批量采集数据（生成原始数据集）**

在 CMD 中循环探测，把输出重定向到文件：
```cmd
chcp 65001
for /l %i in (1,1,100) do ping -n 1 www.baidu.com >> ping_log.txt
tracert -d www.baidu.com > tracert_log.txt
```
另可用 `.bat` 脚本在每条记录前加上时间戳（如 `echo %time% >> ping_log.txt`），便于做时序分析。

**步骤 2　正则提取 RTT，完成结构化处理**

```python
import re
rtts = []
pat = re.compile(r'时间[=<]\s*(\d+)\s*ms')      # 中文系统；英文系统用 time[=<](\d+)ms
with open('ping_log.txt', encoding='utf-8', errors='ignore') as f:
    for line in f:
        m = pat.search(line)
        if m:
            rtts.append(float(m.group(1)))
print('样本数:', len(rtts), '丢包数:', 100 - len(rtts))
```

**步骤 3　统计分析 + 动态异常阈值**

```python
import numpy as np
arr = np.array(rtts)
mean, std = arr.mean(), arr.std()
thr = mean + 2 * std                       # 均值 + 2 倍标准差
anomalies = np.where(arr > thr)[0]         # 异常探测点下标
print(f'均值={mean:.2f}ms 标准差={std:.2f}ms 最小={arr.min():.0f}ms 最大={arr.max():.0f}ms')
print(f'异常阈值={thr:.2f}ms 异常点={anomalies.tolist()}')
```

**步骤 4　可视化（折线图 + 直方图）**

```python
import matplotlib.pyplot as plt
plt.rcParams['font.sans-serif'] = ['SimHei']      # 解决中文乱码
plt.rcParams['axes.unicode_minus'] = False

fig, ax = plt.subplots(1, 2, figsize=(12, 4))
ax[0].plot(arr, label='RTT')
ax[0].axhline(thr, color='red', ls='--', label=f'阈值 {thr:.0f}ms')
ax[0].scatter(anomalies, arr[anomalies], color='red', zorder=3, label='异常点')
ax[0].set_title('延迟时序折线图'); ax[0].set_xlabel('探测序号'); ax[0].set_ylabel('RTT/ms'); ax[0].legend()
ax[1].hist(arr, bins=20, edgecolor='w')
ax[1].set_title('延迟分布直方图'); ax[1].set_xlabel('RTT/ms'); ax[1].set_ylabel('频数')
plt.tight_layout(); plt.savefig('rtt_analysis.png', dpi=150)
```
产出要求：时序图能看到抖动区间，直方图能看出分布是否偏态，异常点已在图中标注。

**步骤 5　解析 Tracert 日志，输出路由分析报告**

```python
import re, pandas as pd
rows = []
pat = re.compile(r'^\s*(\d+)\s+(?:(\d+)\s*ms\s+)?(?:(\d+)\s*ms\s+)?(?:(\d+)\s*ms\s+)?([\d.]+|\*)\s*$')
with open('tracert_log.txt', encoding='utf-8', errors='ignore') as f:
    for line in f:
        m = pat.match(line)
        if m:
            hop, ip = int(m.group(1)), m.group(5)
            vals = [int(x) for x in m.groups()[1:4] if x]
            rows.append({'跳数': hop, '节点IP': ip,
                         '平均延迟(ms)': sum(vals) / len(vals) if vals else None})

df = pd.DataFrame(rows)
print(f'总跳数：{df["跳数"].max()}')
print('高延迟瓶颈节点：')
print(df.sort_values('平均延迟(ms)', ascending=False).head(3))
df.to_excel('route_report.xlsx', index=False)      # 结构化表格输出
```
产出要求：总跳数、每跳 IP 与延迟、瓶颈节点 Top3，并输出为表格（Markdown / Excel）。
