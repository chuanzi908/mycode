# 设计、实验与答辩准备

## 1. 问题和目标

操作系统内核通常负责 TCP，应用通过 socket 使用它。本项目把一个有限 TCP 服务端移到用户空间：Linux socket 客户端仍由内核实现，内核通过路由把目的地址为 10.0.0.2 的 IP 包投递到 TUN；程序从 TUN 读取 IP 包并构造应答。它适合观察协议字段和状态机，并用自动化测试探索异常输入。目标不是取代 Linux TCP。

## 2. 分层与数据路径

1. `client.py` 调用标准 socket 建立连接并发送短消息。
2. `stack.py` 打开 `/dev/net/tun`，通过 `TUNSETIFF` 设置 TUN 和 `IFF_NO_PI`，直接收发 IPv4 数据报。
3. IPv4 解析检查版本、首部长度、总长度、协议号、分片标志和首部校验和；TCP 解析检查首部长度、伪首部与 TCP 校验和。
4. 四元组中服务器地址和端口固定，连接按客户端 IP 和端口索引。收到 SYN 创建状态并生成 SYN+ACK，收到正确 ACK 进入 ESTABLISHED；按序接收数据并回显；收到 FIN 后进入 LAST_ACK，收到对 FIN 的确认后删除连接。
5. `tick` 按一秒间隔重传待确认报文，最多重传五次；空闲连接到期删除。以上是简化策略，不是完整 RFC 的拥塞和计时算法。

校验和采用 16 位字的反码和，将进位折回，再按位取反。TCP 计算覆盖源和目标 IP、协议号、TCP 长度组成的伪首部以及 TCP 首部和负载；验证时完整求和结果应为零。SYN 和 FIN 各消耗一个序号，数据消耗其字节数，ACK 表示下一期望收到的序号。序号按 2^32 回绕。

## 3. 状态和关键检查

```text
无连接 --SYN--> SYN_RECEIVED --正确 ACK--> ESTABLISHED
ESTABLISHED --有序数据--> ESTABLISHED（回显）
ESTABLISHED --FIN--> LAST_ACK --正确 ACK--> 无连接
任意已建立条目 --符合预期序号的 RST--> 无连接
```

握手最后 ACK 必须匹配预期序号和服务端下一个发送序号；不按序的输入得到当前 ACK，不推进接收序号；错误确认号不会释放待确认响应或推进接收序号。状态机每次只保存一个待确认服务端报文，因此属于停止等待式教学实现。连接数上限和空闲超时用于约束资源，不构成完整的安全防护。

## 4. 测试与智能体流程

单包测试 `fuzz.py` 针对截断、比特翻转、长度、标志位、校验和、随机字节生成输入。标志位变异重新计算校验和，以便合法封装能够进入状态机；其余多种算子故意破坏完整性。

状态测试 `agent_fuzz.py` 每个 episode 从固定初始序列号开始，先握手再基于当前状态生成多步输入。测试包括错误序列号、错误 ACK、重复片段、RST、错误校验和以及正常数据/关闭。观察点包括解析成功/失败、建立、数据、关闭、复位和错误 ACK；检查输出是否可解析、异常输入是否错误推进接收序号、是否有未处理异常。失败样本包含每一步的十六进制报文，供重放和分析。

默认的反馈规则根据上一轮是否观察到 FIN 等事件调整权重，完全离线。可选 LLM 模式把上一轮事件、新事件和失败数发给配置的模型，由模型返回受限整数权重并用于下一轮；第一轮固定权重。模型不直接访问 TUN，也不执行生成代码。模型可能输出无效 JSON 或受到网络限制，此时程序报错。这里的“智能体”是有限的观察—策略—执行循环，并非能自主编写、修复协议栈的通用智能体。

## 5. 实验设计和结果解释

建议分别记录：WSL/Linux 版本、Python 版本、项目版本、命令、时间、随机种子、轮数、每轮 episode 数、权重、事件、异常和失败案例。对照实验采用相同预算和多个独立种子：固定权重、反馈规则、大模型策略。可以比较首次观察各事件所需 episode 数、不同种子的事件数量、失败类别和运行时间；结果只适用于已定义的观察点，不能将其叫做代码覆盖率，也不能仅凭一次实验宣称某方法更优。

当前文件夹的 `fuzz-results.json` 和 `agent-results.json` 是离线结果。一次 Ubuntu WSL 实测的 `integration-output` 记录三次连接通过、命名空间清理成功；其抓包可观察握手、回显和关闭。它不能证明大模型接口或所有协议边界已经通过，其他机器仍需实际验证。

## 6. 可扩展方向

可加入重叠片段与乱序重组、窗口管理、拥塞控制、TCP 选项、TIME_WAIT 和更完整的重传计时；还可加入真实代码覆盖率采集、语料最小化、独立协议实现差分对比，以及大模型输出失败原因分析。它们目前均未实现，应作为后续工作而不是已有成果。
