（二）实验一：装载问题——回溯法（子集树）
----------------------------------------------------------------------

1. 算法设计思路

第一步，把原问题转化为"第一艘船的最大装载"。设第一艘船的装入量为 W1，则原问题的要求是：W1 ≤ c1，且剩余重量（总重量 − W1）不超过 c2。因此只需要让第一艘船装得尽可能多，再检验剩余部分能否装进第二艘船即可。

第二步，确定解空间树。对每个集装箱只有"装入船 1"和"不装入船 1（即留给船 2）"两种选择，因此解空间是一棵高度为 n + 1 的子集树，叶结点共 2^n 个，每个叶结点对应一个解向量 x = (x1, x2, …, xn)。

第三步，设计剪枝函数。约束函数用于判断"能否装上船 1"：若 cw + w[i] ≤ c1，则可以进入左子树，否则该分支上的任何方案都会超载，直接剪掉。限界函数用于判断"是否还值得继续搜索"：设 r 为第 i 层之后尚未决策的集装箱重量之和，若把剩下的全部装上仍不能超过当前最优值，即 cw + r ≤ bestw，则以该结点为根的子树中不可能出现更好的解，直接剪掉；因此只有 cw + r > bestw 时才进入右子树。

第四步，设计回溯框架与现场恢复。进入第 i 层时先执行 r −= w[i]，使 r 恰好表示"第 i 个之后"的剩余重量；左分支执行 cw += w[i]，递归返回后立即 cw −= w[i]；函数结束前执行 r += w[i]，保证兄弟分支在正确的现场上继续搜索。

第五步，记录并输出解。只有当 i > n（到达叶结点）时才比较 cw 与 bestw，若更优则更新 bestw 并把当前 x 复制到 bestx——因为只有叶结点处的 x 才是完整的解向量。搜索结束后若 total − bestw ≤ c2 则有解，bestx 即为一种可行装载方案；否则输出"无合理解"。

复杂度分析：最坏情况下每个结点都要扩展，时间为 O(2^n)，空间为递归栈 O(n)；由于限界函数可以在搜索早期淘汰大量分支，实际扩展的结点数远小于 2^n。


2. 源程序（Loading.cpp）

//
// 实验一：装载问题 —— 回溯法
// 输入：集装箱个数 n；各集装箱重量 w[1..n]；两艘轮船的载重量 c1、c2
// 输出：每个集装箱的装载结果 x[1..n]（1 装入第一艘船，0 装入第二艘船）
//
#include <iostream>
using namespace std;

const int MAXN = 100;
int n;                  // 集装箱个数
int w[MAXN];            // 集装箱重量
int c1, c2;             // 两艘轮船的载重量
int cw;                 // 当前已装入第一艘船的重量（current weight）
int bestw;              // 第一艘船当前找到的最大装载重量
int r;                  // 剩余集装箱重量之和
int x[MAXN];            // 当前解向量
int bestx[MAXN];        // 当前最优解向量
long long nodeCnt = 0;  // 扩展结点计数（用于观察剪枝效果）

// 递归回溯：搜索第 i 层（i 从 1 开始，表示正在决定第 i 个集装箱的去向）
void BackTrack(int i)
{
    ++nodeCnt;
    if (i > n)                       // 到达叶结点，得到一个完整装载方案
    {
        if (cw > bestw)              // 只有装得更满时才更新最优解
        {
            bestw = cw;
            for (int j = 1; j <= n; ++j)
                bestx[j] = x[j];
        }
        return;
    }
    r -= w[i];                       // 进入第 i 层，剩余重量中减去 w[i]

    // 左子树：把第 i 个集装箱装上第一艘船，受载重量约束
    if (cw + w[i] <= c1)             // 约束函数：不能超过 c1
    {
        x[i] = 1;
        cw += w[i];
        BackTrack(i + 1);
        cw -= w[i];                  // 回溯，恢复现场
    }

    // 右子树：把第 i 个集装箱留给第二艘船，受限界函数控制
    if (cw + r > bestw)              // 限界函数：剩余全装上也超不过 bestw 就不必搜索
    {
        x[i] = 0;
        BackTrack(i + 1);
    }
    r += w[i];                       // 离开第 i 层，恢复剩余重量
}

int main()
{
    cout << "请输入集装箱个数 n：";
    cin >> n;
    cout << "请输入每个集装箱的重量 w1..wn：";
    for (int i = 1; i <= n; ++i) cin >> w[i];
    cout << "请输入两艘轮船的载重量 c1 c2：";
    cin >> c1 >> c2;

    int total = 0;
    for (int i = 1; i <= n; ++i) total += w[i];
    cw = 0; bestw = 0; r = total;
    BackTrack(1);

    cout << "\n===== 装载问题（回溯法）结果 =====" << endl;
    if (total - bestw > c2)
    {
        cout << "无合理解：第一艘船最多装 " << bestw
             << "，剩余 " << total - bestw << " 已超过 c2 = " << c2 << endl;
        return 0;
    }
    cout << "第一艘船载重 " << bestw << " / " << c1
         << "，第二艘船载重 " << total - bestw << " / " << c2 << endl;
    cout << "解向量 x1..xn：";
    for (int i = 1; i <= n; ++i) cout << bestx[i] << " ";
    cout << endl;
    cout << "船 1 装入的集装箱：";
    for (int i = 1; i <= n; ++i)
        if (bestx[i] == 1) cout << i << "(" << w[i] << ") ";
    cout << endl;
    cout << "船 2 装入的集装箱：";
    for (int i = 1; i <= n; ++i)
        if (bestx[i] == 0) cout << i << "(" << w[i] << ") ";
    cout << endl;
    cout << "搜索过程中扩展的结点数：" << nodeCnt << endl;
    return 0;
}


3. 程序说明

（1）数组 w、x、bestx 均从下标 1 开始使用，与递归层号 i 一一对应，避免了下标换算带来的错误；

（2）r 表示"当前结点之后尚未决策的集装箱重量之和"。进入第 i 层时先执行 r −= w[i]，因此限界条件 cw + r > bestw 中的 r 不含 w[i]，界既紧又不会漏解；

（3）bestw 与 bestx 只在叶结点更新。若在内部结点更新，此时 x[i+1..n] 还没有确定，复制到 bestx 的将是上一轮搜索残留的"半成品"解；

（4）限界函数取严格大于：当 cw + r 恰好等于 bestw 时，子树中最多只能得到与当前最优值相等的解，不会更优，可以安全剪枝；

（5）输出前必须用 total − bestw ≤ c2 再判定一次。回溯只保证"船 1 装得最多"，并没有保证"剩下的装得进船 2"，省略这一步会把不成立的方案当成可行解输出；

（6）nodeCnt 只用于统计扩展结点数，不影响搜索逻辑，便于观察限界函数的剪枝效果。

5. 结果分析

（1）bestw = 152 与 c1 相等，说明第一艘船恰好被装满；剩余重量 130 也恰好等于 c2，说明两艘船同时装满，7 个集装箱全部装船，方案合理。

（2）解向量 x = {1, 0, 1, 0, 0, 1, 1}：第 1、3、6、7 号集装箱装入第一艘船，重量为 90 + 40 + 12 + 10 = 152；第 2、4、5 号装入第二艘船，重量为 80 + 30 + 20 = 130。两船均未超载。

（3）搜索过程只扩展了 24 个结点，而 7 个集装箱的子集树共有 2^8 − 1 = 255 个结点，剪掉了约 90% 的分支，说明约束函数与限界函数都发挥了作用。

（4）手工验算可以印证结果：总重量 90 + 80 + 40 + 30 + 20 + 12 + 10 = 282 = 152 + 130，恰好等于两船载重量之和，因此本题属于"必须精确划分"的情形——只要第一艘船能装到 152，第二艘船必然正好装 130。程序按"先装大箱"的自然顺序深度优先搜索，第一个达到 152 的叶结点即为最优解，bestx 记录正确。

（5）把 c1 改为 150 再运行，结果为 bestw = 150（90 + 40 + 20），剩余 132 > c2 = 130，程序进入"无合理解"分支输出提示；把 c1 改为 148 时 bestw = 142（90 + 40 + 12），剩余 140 > 130，同样无解。两条边界用例都验证了"船 1 装得最多 ≠ 有解"这一判定不能省略。


----------------------------------------------------------------------
（三）实验二：图的 m 着色问题——回溯法（m 叉树）
----------------------------------------------------------------------

1. 算法设计思路

第一步，确定解空间树。把 n 个顶点按编号 1, 2, …, n 依次排列，第 i 层决定顶点 i 的颜色。每个顶点都有 m 种颜色可选，因此解空间是一棵高度为 n + 1 的 m 叉树，叶结点共 m^n 个，每个叶结点对应一个颜色向量 x = (x1, x2, …, xn)，其中 xi ∈ {1, 2, …, m} 表示顶点 i 所着的颜色。

第二步，设计约束函数。顶点按编号顺序着色，当决定顶点 i 的颜色时，顶点 1～i−1 的颜色已经确定，只需检查 i 与这些已着色顶点之间是否存在"同色且有边"的冲突：若存在某个 j < i 满足 c[i][j] = 1 且 x[i] = x[j]，则当前颜色不可用，剪掉以该结点为根的子树；否则该颜色合法，继续为顶点 i + 1 着色。由于无向图的邻接矩阵对称，只查 j < i 的部分即可覆盖所有边。

第三步，统计解的个数。当 i > n 时说明 n 个顶点全部着色完毕且每一步都满足约束，此时得到一个合法方案，计数器 sum 加一，并可打印该方案。

第四步，由方案数反推色数。色数的定义是"使图可以合法着色的最少颜色数"，因此从 k = 1 开始，依次统计颜色数为 k 时的方案数，第一个大于 0 的 k 即为该图的色数。为避免重复打印，单独实现了一个只计数、不输出的回溯函数 CountColorings。

复杂度分析：解空间是一棵 m 叉树，最坏情况下需要遍历全部 m^n 个叶结点，时间为 O(m^n)，空间为递归栈 O(n)。约束函数在每一层都能剪掉相当一部分子树，实际搜索量远小于 m^n。


2. 源程序（MColoring.cpp）

//
// 实验二：图的 m 着色问题 —— 回溯法
// 输入：无向图顶点数 n；n 行邻接矩阵 c；可用颜色数 m
// 输出：合法着色方案总数、部分着色方案，以及该图的色数
//
#include <iostream>
#include <iomanip>
using namespace std;

const int MAXN = 20;
int n;                  // 顶点个数
int m;                  // 颜色数
int c[MAXN][MAXN];      // 邻接矩阵，1 表示有边
int x[MAXN];            // x[i] = j 表示第 i 个顶点着第 j 种颜色
long long sum = 0;      // 着色方案总数
long long nodeCnt = 0;  // 扩展结点计数

// 约束函数：检查第 i 个顶点当前所着颜色是否与相邻顶点冲突
bool Ok(int i)
{
    for (int j = 1; j < i; ++j)          // 只需与前面已确定颜色的顶点比较
        if (c[i][j] == 1 && x[i] == x[j])
            return false;
    return true;
}

// 递归回溯：为第 i 个顶点着色
void BackTrack(int i)
{
    ++nodeCnt;
    if (i > n)                            // 所有顶点均已着色，得到一个可行方案
    {
        ++sum;
        cout << "方案 " << setw(3) << sum << " ： ";
        for (int j = 1; j <= n; ++j)
            cout << "v" << j << "=" << x[j] << (j == n ? "" : "  ");
        cout << endl;
        return;
    }
    for (int col = 1; col <= m; ++col)    // 解空间树为 m 叉树，每个顶点有 m 种选择
    {
        x[i] = col;
        if (Ok(i))                        // 满足约束才继续深搜
            BackTrack(i + 1);             // 否则剪掉以该结点为根的整棵子树
        x[i] = 0;                         // 回溯，恢复现场
    }
}

// 只统计方案数、不打印方案的回溯，用于判定色数
long long CountColorings(int i, int colors)
{
    if (i > n) return 1;
    long long total = 0;
    for (int col = 1; col <= colors; ++col)
    {
        x[i] = col;
        bool ok = true;
        for (int j = 1; j < i; ++j)
            if (c[i][j] == 1 && x[i] == x[j]) { ok = false; break; }
        if (ok) total += CountColorings(i + 1, colors);
        x[i] = 0;
    }
    return total;
}

int main()
{
    cout << "请输入无向图顶点数 n：";
    cin >> n;

（四）实验三：布线问题——分支限界法（队列式）
----------------------------------------------------------------------

1. 算法设计思路

第一步，明确与回溯法的区别。回溯法用深度优先的方式搜索解空间树，一条路走到底再回退；分支限界法用广度优先或最小耗费优先的方式搜索，每个活结点只有一次成为扩展结点的机会，一旦出队（出表）就一次性生成它的全部儿子结点。

第二步，确定解空间的组织方式。把每个可布线的方格看作解空间中的一个状态，从起点 a 出发，每一步只能向上、下、左、右四个方向移动一格，因此每个结点最多有 4 个儿子。目标是找一条从 a 到 b 的路径，并使路径上的方格数（段数）最少。

第三步，选择活结点表。由于每走一步的代价都是 1，路径长度就是扩展的层数，因此用先进先出队列（FIFO）作为活结点表即可：先入队的结点层次更浅，出队顺序天然按距离递增，这就是队列式分支限界。若各步代价不同，则必须改用优先队列（最小堆）式分支限界，每次取出当前耗费最小的活结点扩展，才能保证首次到达目标时最优。

第四步，设计剪枝与标记。一个方格若越界、已被封锁（array = 1）或已经被访问过（dist ≠ −1），都不再入队：越界与封锁是约束，已访问是剪枝——同一个方格被第二次到达时，路径长度一定不小于第一次，再扩展只会得到更差的解。

第五步，记录路径。用 dist 数组记录起点到每个方格的最短布线长度，用 from 数组记录每个方格是从哪个方格扩展来的（前驱）。当队列中第一次弹出终点 b 时，dist[b] 即为最短布线长度；再从 b 沿 from 反向回溯到 a，即可得到一条最短布线路径。

复杂度分析：每个方格最多入队一次、出队一次，每次扩展检查 4 个方向，故时间复杂度为 O(n²)，空间复杂度为 O(n²)（dist、from 两个数组与队列）。与回溯法"列举所有路径再取最小"的指数级复杂度相比，分支限界法在这里是多项式时间的。


2. 源程序（Wiring.cpp）

//
// 实验三：布线问题 —— 分支限界法（队列式）
// 输入：阵列规模 n；n 行 n 列布线阵列（0 可布线，1 已封锁）；
//       起点 a(r,c)、终点 b(r,c)（行列均从 1 开始）
// 输出：a 到 b 的最短布线长度，以及一条最短布线路径
//
#include <iostream>
#include <iomanip>
#include <queue>
using namespace std;

const int MAXN = 50;
struct Position {          // 方格坐标
    int row, col;
};
int n;                     // 阵列规模
int grid[MAXN][MAXN];      // 0 可布线，1 已封锁
Position a, b;             // 起点、终点
int dist[MAXN][MAXN];      // 起点到各方格的最短布线长度，-1 表示不可达
Position from[MAXN][MAXN]; // 记录前驱方格，用于回溯路径
long long nodeCnt = 0;     // 出队的活结点个数

// 四个方向：上、下、左、右
const int dr[4] = { -1, 1, 0, 0 };
const int dc[4] = { 0, 0, -1, 1 };

bool InRange(int r, int c)
{
    return r >= 1 && r <= n && c >= 1 && c <= n;
}

// 队列式分支限界（本质上是按层次扩展的 BFS）
int ShortestPath()
{
    for (int i = 1; i <= n; ++i)
        for (int j = 1; j <= n; ++j)
            dist[i][j] = -1;

    queue<Position> q;                  // 活结点表：先进先出队列
    dist[a.row][a.col] = 0;
    q.push(a);

    while (!q.empty())
    {
        Position cur = q.front(); q.pop();      // 取队首活结点作为当前扩展结点
        ++nodeCnt;
        if (cur.row == b.row && cur.col == b.col)   // 首次到达终点即为最短
            return dist[b.row][b.col];

        for (int k = 0; k < 4; ++k)                 // 沿直线或直角方向扩展
        {
            int nr = cur.row + dr[k];
            int nc = cur.col + dc[k];
            if (!InRange(nr, nc)) continue;         // 越界
            if (grid[nr][nc] == 1) continue;        // 被封锁的方格不能通过
            if (dist[nr][nc] != -1) continue;       // 已到达过，剪枝
            dist[nr][nc] = dist[cur.row][cur.col] + 1;
            from[nr][nc] = cur;
            q.push({ nr, nc });                     // 新结点加入活结点表
        }
    }
    return -1;                                      // 队列空仍未到达，说明不可达
}

int main()
{
    cout << "请输入阵列规模 n：";
    cin >> n;
    cout << "请依次输入 " << n << " 行布线阵列（0 可布线，1 已封锁）：" << endl;
    for (int i = 1; i <= n; ++i)
        for (int j = 1; j <= n; ++j)
            cin >> grid[i][j];
    cout << "请输入布线起点 a（行 列）：";
    cin >> a.row >> a.col;
    cout << "请输入布线终点 b（行 列）：";
    cin >> b.row >> b.col;

    int len = ShortestPath();

    cout << "\n===== 布线问题（分支限界法）结果 =====" << endl;
    if (len < 0)
    {
        cout << "a 到 b 不可达，无布线方案。" << endl;
        return 0;
    }
    cout << "a(" << a.row << "," << a.col << ") 到 b(" << b.row << "," << b.col
         << ") 的最短布线长度为：" << len << endl;
    cout << "出队的活结点个数：" << nodeCnt << endl;

    // 由前驱数组从终点回溯到起点，得到路径
    Position path[MAXN * MAXN];
    int cnt = 0;
    Position cur = b;
    while (true)
    {
        path[cnt++] = cur;
        if (cur.row == a.row && cur.col == a.col) break;
        cur = from[cur.row][cur.col];
    }
    cout << "一条最短布线路径：" << endl;
    for (int i = cnt - 1; i >= 0; --i)
    {
        cout << "(" << path[i].row << "," << path[i].col << ")";
        if (i > 0) cout << " -> ";
    }
    cout << endl;

    // 打印距离标记阵列，便于核对布线过程（* 封锁方格，- 不可达）
    cout << "\n距离标记阵列：" << endl;
    for (int i = 1; i <= n; ++i)
    {
        for (int j = 1; j <= n; ++j)
        {
            cout << setw(4);
            if (grid[i][j] == 1)      cout << "*";
            else if (dist[i][j] < 0)  cout << "-";
            else                      cout << dist[i][j];
        }
        cout << endl;
    }
    return 0;
}


3. 程序说明

（1）方格坐标统一采用 1-based（行、列均从 1 开始），InRange 同时判断上下界，避免越界访问；

（2）dist 初始化为 −1 而不是 0。0 是"起点到自身"的合法距离，若用 0 表示"未访问"，起点的距离就会与未访问标志混淆，终点不可达时也会与"距离为 0"无法区分；

（3）四个方向用数组 dr[4]、dc[4] 表示，循环展开即可实现"只沿直线或直角布线"的约束；

（4）入队前就写好 dist 并据此判重（dist[nr][nc] != −1 则跳过）。若等到出队时才标记，同一个方格会被多次入队、重复扩展，dist 还可能被后到的更长路径覆盖；

（5）首次弹出终点即返回，不必等队列空。这是队列式分支限界的"最优性"依据：出队顺序按距离非降，第一次到达 b 的路径一定最短；

（6）若队列为空仍未到达 b，返回 −1，主程序据此输出"不可达"；起点与终点重合时 dist = 0，第一次弹出即返回 0，无需特殊处理。

（五）回溯法与分支限界法的对比分析
----------------------------------------------------------------------

对比项　　　　回溯法　　　　　　　　　　　　　分支限界法
搜索方式　　　深度优先，一条路走到底，失败再回退　广度优先（队列式）或最小耗费优先（优先队列式）
结点扩展　　　结点在回溯过程中可多次成为扩展结点　每个活结点只有一次成为扩展结点的机会，出队即扩展，且一次性生成全部儿子
存储结构　　　只需保存当前路径的递归栈，空间 O(n)　需要维护活结点表，空间 O(2^n) 或 O(n²)
求解目标　　　找出全部解，或判断是否存在可行解　找最优解（路径最短、耗费最小等）
剪枝手段　　　约束函数＋限界函数　　　　　　　　　约束函数＋限界函数＋活结点表去重
本实验应用　　装载问题（子集树）、图的 m 着色（m 叉树）　布线问题（n×n 方格图上的最短路径）

结论：回溯法实现简单、空间开销小，适合"求全部可行解或判定可行性"的问题；分支限界法通过活结点表控制扩展顺序，能够保证第一次到达目标结点时即为最优解，适合"求最优解"的问题，代价是需要额外的存储空间。两者都以解空间树为基础，都以约束函数和限界函数剪枝，区别在于搜索顺序与求解目标。

"这是队列式分支限界求布线最短路的实现，请指出判重时机、dist 初值、首次到达终点的处理三处是否存在缺陷。"

2. 使用效果

（1）定位错误更快。装载问题 bestw 偏小的问题，AI 给出了"r 的语义""内部结点更新""c1/c2 判定"三个排查方向，按第一、第三个方向各改一处即修复，比逐行打断点快得多。

（2）对两类算法差异的理解更具体。AI 用"每个活结点只有一次出队扩展的机会"来概括分支限界法与回溯法的区别，比教材的定义更容易记住，也直接解释了"布线为什么必须用队列、不能用递归回溯"。

（3）AI 也会给出不严谨的结论。我曾问"装载问题的限界函数能不能写成 cw + r ≥ bestw"，AI 回答"可以，还能多剪一些"。实际推演表明：等号情况下虽然不会丢掉"更优解"，但会把"追平最优值"的分支整棵剪掉，如果题目要求输出全部最优方案就会漏解。最终以推演结果为准，改回严格大于。

（4）需要人工把关的地方。AI 生成的随机测试脚本第一版把阵列中 0/1 的含义弄反了（把 0 当成封锁），导致 200 组数据全部"不可达"，排查后才发现是数据生成端的问题。这说明 AI 产出的测试代码同样要与题目约定逐项核对，不能直接采信。

3. 使用体会

AI 在本实验中最有价值的地方，是把模糊的直觉变成可检验的清单：限界函数里 r 到底扣没扣当前层、队列判重放在入队前还是出队后、冲突检测要与哪些顶点比较，这些细节靠肉眼读代码很难发现，但让 AI 列出易错点后逐条自查，效率明显提高。它也很适合承担"复述思路""生成测试""整理格式"这类重复劳动。

但算法的正确性最终只能由运行结果和数学推演来确认。本次实验里最有价值的一次 AI 使用，恰恰是我用推演推翻了 AI 关于"≥ 也能剪枝"的结论的那一次——AI 的解释只能作为线索，能不能写进报告，取决于它是否经得起程序与证明的双重检验。

六、【错误分析】
======================================================================

实验过程中主要在以下几个方面出现过问题，逐项分析现象、原因与解决办法。

（一）在内部结点更新 bestw 与 bestx，输出了"半成品"解

现象：bestw 的数值能与手算对上（152），但打印出来的解向量 x 后几位与实际装载情况不符，按 x 反算船 1 的重量得不到 152。

原因：第一版把 if (cw > bestw) { bestw = cw; 复制 x 到 bestx; } 写在了递归函数的开头，而不是叶结点分支里。此时递归还在第 i 层，x[i+1..n] 尚未赋值，保留的是上一条分支的残留值，复制到 bestx 的当然是"半成品"。

解决：把最优解的更新严格限定在 i > n 的叶结点分支内：只有叶结点处的 x 才是完整的解向量，也才能用来计算 cw。修改后 bestw 与 bestx 始终对应同一个方案。

（二）忘记判定第二艘船，把"船 1 装得最多"当成"有解"

现象：把 c1 改为 148 时，程序仍然输出"船 1 载重 142 / 148，船 2 载重 140 / 130"，并给出解向量；但第二艘船只装得下 130，140 的货物根本装不进去，方案是假的。

原因：回溯过程只优化了"第一艘船装多少"这一个目标，并没有把"剩余部分能否装入第二艘船"纳入判定。bestw 只是"第一艘船的最大装载量"，它不等于"问题有解"。

解决：在搜索结束后补上判定：若 total − bestw ≤ c2 才输出方案，否则输出"无合理解"。改后用 c1 = 148、150 两组数据验证，程序都正确进入了无解分支（剩余分别为 140、132，均大于 130）。

（三）回溯时未恢复 cw 与 r，兄弟分支的现场被污染

现象：bestw 显著小于手算结果，且把输入数据的顺序调整一下，输出就变了，结果不稳定。

原因：左分支执行了 cw += w[i] 却没有在递归返回后执行 cw −= w[i]；r −= w[i] 也没有在函数末尾补回。这样回到上层继续搜索右分支时，cw 与 r 都停留在"已经装进去"的状态，限界函数的估值全部偏大或偏小，本应搜索的分支被误剪。

解决：把"进入时修改、返回时恢复"成对书写：左分支前后 cw 加、减各一次，函数进出口 r 减、加各一次。恢复现场是回溯法的固定动作，漏掉任何一处都会让整棵树的计算基准错乱。

（四）m 着色的冲突检测只与 i−1 比较，方案数虚高

现象：方案数输出 324，而正确答案是 48；打印出的方案里也存在相邻顶点同色的情况。

原因：Ok(i) 写成了只判断 c[i][i−1] == 1 && x[i] == x[i−1]，只检查了顶点 i 与它前一个顶点之间的一条边，漏掉了 i 与更早顶点之间的边（例如 v4 与 v1、v2 都有边）。冲突没被检出，本应剪掉的子树继续向下搜索，于是方案数被放大。

解决：Ok(i) 必须遍历 j = 1..i−1，凡 c[i][j] == 1 且 x[i] == x[j] 即判为冲突。修改后方案数回到 48，与"K4 的 4! 种排列 × v5 的 2 种可选颜色"的手算结果一致。

（五）用深度优先搜索求布线，得到的是"一条路"而不是"最短路"

现象：第一版按回溯法写布线程序，第一次到达 b 就返回，输出的布线长度是 17；而阵列中明显存在更短的路径。

原因：深度优先搜索沿一个方向走到底，第一次到达终点的那条路径只是"搜索顺序上最先碰到"的一条可行路径，与长度无关。要得到最短路径，必须枚举所有路径再取最小，而路径数量随方格规模指数增长，完全不可行。

解决：改用分支限界法：用 FIFO 队列按层扩展，dist 记录层号，第一次弹出 b 时即为最短；同时用 dist 判重剪枝。改后输出长度为 9，与独立 BFS 的结果一致。这也说明"求最优解"应当优先考虑分支限界法而不是回溯法。

（六）入队时未标记，同一方格被重复扩展

现象：布线长度偶尔偏大，队列长度异常增长，规模稍大的阵列运行时间明显变长。

原因：判重写在了"出队"处：结点入队时没有立即写 dist，同一个方格可能被上下左右四个邻居各入队一次，出队后又被重复扩展；后到的更长路径还会覆盖先前写入的 dist，使距离标记失去"最短"的含义。

解决：把标记提前到入队之前：先写 dist[nr][nc] = dist[cur] + 1，再 push。这样每个方格最多入队一次，dist 一经写入就是最短距离，队列规模也被控制在方格总数以内。

（七）验证：交叉对拍与边界用例

为避免"程序跑出了结果就认为对"的误判，另外做了三重校验：一是用暴力枚举复核装载问题——枚举 7 个集装箱的全部 2^7 = 128 个子集，求不超过 c1 的最大子集和，结果 152 与回溯法一致；二是用五重循环枚举 4^5 = 1024 种着色，统计合法方案数为 48，与回溯法一致；三是用一份独立的 BFS 实现复核布线长度，同样得到 9。

此外还构造了边界用例：c1 取 150、148 时验证无解分支；布线起点与终点重合时验证长度为 0；把终点改到被封锁带隔开的区域验证"不可达"分支。三组边界用例全部通过，说明程序在正常与异常输入下都能给出正确结果。


======================================================================
七、【实验总结】
======================================================================

（1）回溯法的通用框架在三个问题中得到了完整体现：先定义解空间树（装载问题是子集树、m 着色是 m 叉树），再确定约束函数与限界函数，然后按深度优先的顺序搜索，最后在叶结点处记录或输出解。三个步骤中，"解空间树的形态"决定了搜索的基本复杂度，"剪枝函数"决定了实际搜索量。

（2）剪枝是回溯法效率的核心。装载问题的满二叉子树有 255 个结点，限界函数把扩展结点压到 24 个；m 着色的 4 叉树前 5 层有 1365 个结点，约束函数把扩展结点压到 113 个。两者都剪掉了 90% 左右的搜索空间，而剪枝函数本身只是一次比较或一次循环，代价极低。

（3）分支限界法"首次到达即最优"依赖于代价的单调性。布线问题每走一步代价都是 1，FIFO 队列的出队顺序天然按距离非降，所以第一次弹出 b 时的路径一定最短；如果各段代价不同，就必须改用优先队列式（最小堆）分支限界，每次取出当前耗费最小的活结点，否则首次到达不能保证最优。

（4）两类算法的"空间换时间"特征很鲜明：回溯法只需 O(n) 的递归栈，分支限界法却要维护 O(2^n) 或 O(n²) 的活结点表。布线问题若用回溯法枚举路径，时间是指数级；改成队列式分支限界后，每个方格只入队一次，时间降到 O(n²)，代价是多用了 dist、from 两个数组。

（5）正确性验证不能只看"程序跑出来了"。本实验先用暴力枚举与独立实现对拍，再补边界用例，才确认最优分支与无解分支同时正确。尤其是装载问题"船 1 装得最多 ≠ 有解"这一条，如果不构造 c1 = 148 这样的用例，很容易把假方案当成正确答案提交。

（6）收获与不足。收获在于不再把回溯法当成"写个递归就行"，而是能按"解空间树—剪枝函数—现场恢复—解的记录"四步独立设计，也能根据问题性质在回溯法与分支限界法之间做出选择。不足有三点：装载问题没有对 w 做降序预处理，先装大箱可以更快逼近最优、让限界函数剪得更狠；m 着色按顶点编号顺序着色，若改成"按度数从大到小"的顺序，冲突会更早暴露，搜索量还能再降；布线问题只实现了 FIFO 队列式，没有与优先队列式做耗时对比。后续可以把这三项改进补上，并扩展到 20×20 以上的阵列做性能测试。
