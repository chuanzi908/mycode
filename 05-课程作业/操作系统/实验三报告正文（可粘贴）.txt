一、实验目的

本实验以请求页式存储管理为对象，通过编制一个模拟程序，用随机指令流驱动五种页面置换算法，达到以下目的：

1．理解虚拟存储技术“部分装入、按需调页”的基本特点，弄清页式存储管理中地址变换、缺页中断与页面置换三者的关系；
2．掌握用 srand()、rand() 按程序局部性原理构造指令地址流，并按“每页 10 条指令”把指令地址流变换为页地址流的方法；
3．掌握先进先出（FIFO）、最近最少使用（LRU）、最佳淘汰（OPT）、最少访问页面（LFU）、最近最久不经常使用（NUR）五种页面置换算法的基本思想、数据结构与实现过程；
4．掌握用命中率（命中率＝1－页面失效次数/页地址流长度）定量评价算法效率的方法，并能分析内存容量、程序局部性对命中率的影响；
5．用实验数据验证理论结论：OPT 为理论最优但不可实现；LRU 具有栈式性质，FIFO 不具备栈式性质（可能出现命中率随容量增加反而下降的反常现象）。

二、实验要求

1．用随机数产生 320 条指令的指令序列。指令地址按以下原则生成：50% 的指令顺序执行，25% 的指令均匀分布在前地址部分，25% 的指令均匀分布在后地址部分；具体按“随机起点 m → 执行 m+1 → 在前地址 [0,m+1] 中随机取 m´ → 执行 m´+1 → 在后地址 [m´+2,319] 中随机取一条”五步循环，直到产生 320 条指令；
2．将指令序列变换为页地址流：页面大小 1KB，每页存放 10 条指令，用户虚存容量 32KB（32 页），用户内存容量取 4~32 页；
3．在同一个程序文件中实现 FIFO、LRU、OPT、LFU、NUR 五种页面置换算法的内存分配与回收过程；
4．对内存容量 4、8、12、16、20、24、28、32 页分别运行五种算法，按“命中率＝1－页面失效次数/页地址流长度”计算命中率并比较其效率；
5．用 vi 编辑源程序，用 gcc 编译链接，用 ./ 运行，并保存编辑、编译、运行过程的终端截图；
6．记录 AI 的使用过程与实际效果（编码对比、优化、查错等），配截图说明。

四、实验内容与实现

4.1　指令序列与页地址流的生成

4.1.1　设计思路

真实程序的访存序列无法在实验中复现，因此用一个带局部性的随机模型来“造”指令流：让大部分指令集中在少数几个地址区间内连续执行，少量指令跳到远处。这正对应程序中顺序结构、循环结构和转移指令的混合。

指导书给出的五步生成法中，前三步决定了地址的分布：步骤②使 m 与 m+1 相邻，构成一次顺序执行；步骤③在小地址范围内随机取点，模拟向前跳转（如循环体）；步骤⑤在大地址范围内随机取点，模拟向后跳转（如函数调用返回后跳走）。这里有一个容易被忽略的细节：步骤⑤取到的地址必须作为下一轮的起点 m，否则每一轮只能产生 2 条顺序相关的指令（m+1、m´+1）而总共产生 5 条指令，顺序执行的比例只有 40%；把⑤的结果作为下一轮起点后，每轮只新增 4 条指令，其中 m+1、m´+1 两条继承上一轮的顺序关系，比例正好是 50%。

地址与页面的对应关系按“每页 10 条指令”换算：第 0~9 条指令属第 0 页，第 10~19 条属第 1 页，……，第 310~319 条属第 31 页，即 page = address / 10。指令地址取值范围为 0~319，除 10 后恰好落在 0~31，共 32 页，与虚存容量一致。

4.1.2　生成函数

/* 生成 320 条指令的指令地址流：50% 顺序、25% 前地址、25% 后地址 */
static void create_instr(void)
{
    int i = 0, m, m1, lo;

    srand((unsigned)time(NULL));
    m = rand() % N;                 /* ① 在 [0,319] 中随机选取起点 m */
    instr[i++] = m;

    while (i < N) {
        instr[i++] = (m + 1) % N;   /* ② 顺序执行 m+1 */
        if (i >= N) break;

        m1 = rand() % (m + 2);      /* ③ 前地址 [0,m+1] 中随机取 m´ */
        instr[i++] = m1;
        if (i >= N) break;

        instr[i++] = (m1 + 1) % N;  /* ④ 顺序执行 m´+1 */
        if (i >= N) break;

        lo = m1 + 2;                /* ⑤ 后地址 [m´+2,319] 中随机取一条 */
        if (lo > N - 1) lo = N - 1;
        m = lo + rand() % (N - lo); /* 该地址作为下一轮的起点 */
        instr[i++] = m;
    }
}

/* 把指令地址流变换为页地址流 */
static void to_page(void)
{
    int i;
    for (i = 0; i < N; i++)
        page[i] = instr[i] / PER_PAGE;   /* 每页 10 条指令 */
}

代码中 % N 与 lo > N-1 的处理是为了防止 m+1、m´+2 越过 319 造成数组越界：m 取 319 时 m+1 回绕到 0，m´ 取 318、319 时后地址区间退化为 [319,319]，此时随机结果只能是 319。

4.2　五种页面置换算法的实现

各算法共用同一组全局变量：instr[320] 保存指令地址流，page[320] 保存页地址流，frames 表示当前用户内存容量的页框数，函数返回值为页面失效次数。

4.2.1　先进先出置换算法（FIFO）

FIFO 按页面调入内存的先后次序淘汰，最先进的页面最先被换出。实现上用一个循环队列表示内存，front 指向“最早调入”的那个页框，每次置换后 front 后移一位。

static int fifo(void)
{
    int mem[MAXF], front = 0, i, j, fault = 0, hit;

    for (i = 0; i < frames; i++) mem[i] = -1;
    for (i = 0; i < N; i++) {
        hit = 0;
        for (j = 0; j < frames; j++)
            if (mem[j] == page[i]) { hit = 1; break; }
        if (hit) continue;               /* 命中，不作置换 */
        fault++;
        mem[front] = page[i];            /* 淘汰最先调入的页面 */
        front = (front + 1) % frames;
    }
    return fault;
}

FIFO 的优点是实现简单、只需一个指针，缺点是完全没有利用“最近是否访问过”的信息，把长期驻留的热点页也按时间淘汰掉。理论上它有 Belady 异常：增加页框数反而可能使失效次数增多，因为它的被置换集合不满足包含关系。

4.2.2　最近最少使用置换算法（LRU）

LRU 淘汰“最长时间没有被访问”的页面，它认为过去一段时间没被访问的页，将来短时间内也不会被访问。实现上给每个页框配一个时间戳 last[]，每次命中就把它更新为当前时刻，置换时挑时间戳最小（最久未用）的页框。

static int lru(void)
{
    int mem[MAXF], last[MAXF], i, j, k, clock = 0, fault = 0, hit;

    for (i = 0; i < frames; i++) { mem[i] = -1; last[i] = -1; }
    for (i = 0; i < N; i++, clock++) {
        hit = 0;
        for (j = 0; j < frames; j++)
            if (mem[j] == page[i]) { hit = 1; last[j] = clock; break; }
        if (hit) continue;
        fault++;
        k = 0;
        for (j = 1; j < frames; j++)
            if (last[j] < last[k]) k = j;    /* 找最久未被访问的页框 */
        mem[k] = page[i];
        last[k] = clock;
    }
    return fault;
}

LRU 具有栈式性质：容量为 n 时驻留的页面集合一定是容量为 n+1 时的子集，因此失效次数随容量单调不增，不会出现 Belady 异常。代价是需要为每个页框维护访问时间，纯软件实现的开销较大。

4.2.3　最佳淘汰算法（OPT）

OPT 淘汰“将来最长时间不会被访问”的页面，它需要向后看：对内存中每个页面，在剩余页地址流中查找它下一次出现的位置，取位置最靠后（或今后不再出现）的那一页换出。

static int opt(void)
{
    int mem[MAXF], i, j, k, fault = 0, hit, pos, far, next;

    for (i = 0; i < frames; i++) mem[i] = -1;
    for (i = 0; i < N; i++) {
        hit = 0;
        for (j = 0; j < frames; j++)
            if (mem[j] == page[i]) { hit = 1; break; }
        if (hit) continue;
        fault++;

        pos = -1;
        for (j = 0; j < frames; j++)         /* 先占用空闲页框 */
            if (mem[j] == -1) { pos = j; break; }
        if (pos < 0) {                       /* 无空闲页框，向后看将来 */
            far = -1; pos = 0;
            for (j = 0; j < frames; j++) {
                next = N;                    /* 今后不再使用，视为最远 */
                for (k = i + 1; k < N; k++)
                    if (page[k] == mem[j]) { next = k; break; }
                if (next > far) { far = next; pos = j; }
            }
        }
        mem[pos] = page[i];
    }
    return fault;
}

这里把“今后不再出现”的 next 取为 N（大于任何合法下标），保证这类页面优先被淘汰，这是实现 OPT 最容易写错的地方——若把 next 取成 0，逻辑正好反了。OPT 需要预知未来的访问序列，实际系统中无法实现，只作为衡量其他算法优劣的理论下界。

4.2.4　最少访问页面算法（LFU）

LFU 以“历史访问次数”作为淘汰依据，淘汰访问次数最少的页面。实现上为每个页框维护计数 cnt[]，命中则加一；置换时取 cnt 最小的页框。若计数相同则按调入先后（load[] 记录调入序号）淘汰更早调入的，以避免结果依赖数组遍历顺序而不可复现。

static int lfu(void)
{
    int mem[MAXF], cnt[MAXF], load[MAXF], i, j, fault = 0, hit, pos, seq = 0;

    for (i = 0; i < frames; i++) { mem[i] = -1; cnt[i] = 0; load[i] = 0; }
    for (i = 0; i < N; i++) {
        hit = 0;
        for (j = 0; j < frames; j++)
            if (mem[j] == page[i]) { hit = 1; cnt[j]++; break; }
        if (hit) continue;
        fault++;

        pos = -1;
        for (j = 0; j < frames; j++)
            if (mem[j] == -1) { pos = j; break; }
        if (pos < 0) {
            pos = 0;
            for (j = 1; j < frames; j++)
                if (cnt[j] < cnt[pos] ||
                    (cnt[j] == cnt[pos] && load[j] < load[pos]))
                    pos = j;                 /* 次数最少，平局取调入早者 */
        }
        mem[pos] = page[i];
        cnt[pos] = 1;
        load[pos] = ++seq;
    }
    return fault;
}

LFU 的问题在于计数只增不减：程序早期的热点页即使后面再也不访问，计数依然很高，会长期占据页框，这种现象通常称为“缓存污染”。只有在计数定期衰减（如每隔一段时间右移一位）时，LFU 才能反映近期访问情况。

4.2.5　最近最久不经常使用算法（NUR）

NUR 是 LRU 的低成本近似。它不为每个页面记录精确时间，只设 1 位访问位：被访问过的页置 1；置换时用一个指针循环扫描，遇到访问位为 1 的页就把它清零并给“第二次机会”，继续向后找，遇到访问位为 0 的页则将其淘汰。这实际上就是简单 Clock 算法。

static int nur(void)
{
    int mem[MAXF], ref[MAXF], ptr = 0, i, j, fault = 0, hit, free_i;

    for (i = 0; i < frames; i++) { mem[i] = -1; ref[i] = 0; }
    for (i = 0; i < N; i++) {
        hit = 0;
        for (j = 0; j < frames; j++)
            if (mem[j] == page[i]) { ref[j] = 1; hit = 1; break; }
        if (hit) continue;
        fault++;

        free_i = -1;
        for (j = 0; j < frames; j++)
            if (mem[j] == -1) { free_i = j; break; }
        if (free_i >= 0) {                   /* 仍有空闲页框 */
            mem[free_i] = page[i];
            ref[free_i] = 1;
            ptr = (free_i + 1) % frames;
            continue;
        }
        while (ref[ptr] == 1) {              /* 访问位为 1，给第二次机会 */
            ref[ptr] = 0;
            ptr = (ptr + 1) % frames;
        }
        mem[ptr] = page[i];
        ref[ptr] = 1;
        ptr = (ptr + 1) % frames;
    }
    return fault;
}

循环队列的指针必须取模回绕，否则扫到数组末尾就会越界；while 循环一定能终止，因为最坏情况下指针转一圈会把所有访问位清零，第二次必能找到 0。NUR 只需要 1 位访问位和 1 个指针，硬件实现代价远低于 LRU 的时间戳或栈，所以真实操作系统（如 Linux 的页面回收）普遍采用 Clock 一类的近似算法。

4.3　主程序与编译运行

主程序把五个算法放进一个函数指针数组，用同一个页地址流依次调用，对每种内存容量输出命中率。

int main(void)
{
    int (*alg[5])(void) = { fifo, lru, opt, lfu, nur };
    const char *name[5] = { "FIFO", "LRU", "OPT", "LFU", "NUR" };
    int i, a, f;

    create_instr();
    to_page();

    printf("指令地址流（前 40 条）：\n");
    for (i = 0; i < 40; i++) printf("%3d%s", instr[i], (i % 20 == 19) ? "\n" : " ");
    printf("\n页地址流（前 40 个）：\n");
    for (i = 0; i < 40; i++) printf("%3d%s", page[i], (i % 20 == 19) ? "\n" : " ");

    printf("\n页框数   FIFO     LRU      OPT      LFU      NUR\n");
    for (frames = 4; frames <= 32; frames += 4) {
        printf("%5d  ", frames);
        for (a = 0; a < 5; a++) {
            f = alg[a]();
            printf(" %7.2f%%", (1.0 - (double)f / N) * 100.0);
        }
        printf("\n");
    }

    printf("\n各算法在 8 页内存下的失效次数：\n");
    frames = 8;
    for (a = 0; a < 5; a++) {
        f = alg[a]();
        printf("  %-5s 失效 %3d 次，命中率 %.2f%%\n", name[a], f,
               (1.0 - (double)f / N) * 100.0);
    }
    return 0;
}

把 4.1、4.2 各段函数与本节 main() 按顺序拼接，加上 #include <stdio.h>、<stdlib.h>、<time.h> 和宏定义（N=320、PER_PAGE=10、MAXF=32）以及三个全局数组，就构成完整的 page.c。

编译与运行在 Linux 终端中依次执行：

$ vi page.c              # 按 i 进入插入模式输入源程序，Esc 后 :wq 保存退出
$ gcc page.c -o page -Wall   # 编译并链接，-o 指定可执行文件名
$ ./page                 # 运行

4.5　结果分析

（1）命中率随内存容量增加而提高。页框数由 4 增到 32，FIFO 从 56.25% 升到 90.00%，OPT 从 65.31% 升到 90.00%。原因是页框越多，能同时驻留的页面越多，进程的工作集越容易被整体装下，缺页概率随之下降。这也说明虚拟存储的性能最终受限于分配到的物理页框数，“加大内存”比“换更好的置换算法”收益更直接。

（2）OPT 在每一种容量下都是最高的，构成命中率的上界：4 页时比 LRU 高 8.75 个百分点，8 页、12 页时高 12.5 个百分点，16 页时高 8.44，20 页时高 5.0，24 页时高 4.06，28 页时高 1.88，到 32 页时差距归零。差距随容量增大而单调收窄，说明内存越充足，“淘汰谁”这个决策越不重要；反之在内存紧张时，算法优劣的影响非常显著（4 页时最好与最差相差 11.56 个百分点）。

（3）LRU 与 FIFO 互有胜负，并未出现“LRU 永远优于 FIFO”的结果。在 8、16、20、24 页时 LRU 分别高出 1.26、1.25、3.44、2.50 个百分点；但在 12 页和 28 页被 FIFO 反超（69.38% 对 68.75%，88.44% 对 88.12%）。这与二者的理论性质一致：LRU 是栈式算法，命中率随容量单调不降，且总能在“最近性”意义下做出比 FIFO 更合理的判断；而 FIFO 只看调入时间，不具备栈式性质，在特定访问序列下可能表现更好（甚至出现 Belady 异常）。本实验只有 320 条指令、17 个左右的热点页，样本规模小，约 1 个百分点量级的差异也包含随机波动，所以不能据一两组数据断言优劣。

（4）NUR 与 LRU 非常接近，全程相差不超过 2 个百分点（最大 1.88，出现在 20 页），8 页时仅差 0.32（61.56% 对 61.88%）；12 页时 NUR 反而略高于 LRU（69.38% 对 68.75%），说明近似算法并不必然更差，具体结果与访问序列有关。这正是 Clock 类算法被实际系统采用的原因：用 1 位访问位近似“最近是否用过”，精度损失很小，而硬件代价从“每页一个时间戳/一个栈节点”降到“每页 1 位 + 一个指针”。

（5）LFU 的表现与内存容量关系最复杂：4 页、12 页时它最低（53.75%、68.44%，比同容量下的 FIFO 还低 2.5 和 0.94 个百分点）；8 页、16 页时与 FIFO 基本持平（60.94% 对 60.62%，75.62% 对 75.31%）；到 20 页时升至 81.56%，超过 FIFO 但仍低于 LRU；24 页时达到 86.25%，反超 LRU 与 FIFO，仅次于 OPT。原因是 LFU 的计数只累加不衰减：程序前期的热点页计数很高，后面即使不再访问也长期占着页框，把真正要用的新页挤出去；页框少时置换频繁，这个缺陷被放大；页框多时置换次数少，保留高频页反而成了优点。若给计数加定期衰减（每访问若干次全部右移一位），LFU 在内存紧张时的表现会明显改善。

（6）32 页时五种算法结果完全相同，都是 90.00%。320 条指令的页面号落在 0~31 之间，32 个页框足以把全部页面装入，此后不再发生置换，失效次数等于该指令流实际涉及的页面个数（本次运行恰好覆盖全部 32 页，故为 32），命中率上限为 1－32/320＝90%，这也是本实验命中率的理论上限。它说明：当内存能装下整个工作集时，置换算法的选择没有意义，此时页面失效全部来自“首次访问”引起的强制性失效。

七、AI 使用说明

本实验的编码与排错过程中使用了 AI 对话助手，主要用于“理清规则、对比方案、检查逻辑”三类工作，具体记录如下。

7.1　环节一：澄清指令流的生成规则

提示词：“指导书要求 50% 指令顺序执行、25% 前地址、25% 后地址，按①~⑤五步循环生成 320 条指令，但按字面实现时顺序执行只有 40%，问题出在哪？”

AI 的回答指出了关键：步骤⑤取到的地址要作为下一轮的起点 m，这样每轮新增 4 条指令（m+1、m´、m´+1、新的 m），其中两条继承上一轮的顺序关系，比例才是 50%；如果每轮把①的“重新随机取 m”也当成新指令，比例就会掉到 40%。我据此改写 create_instr()，统计生成结果中 (x, x+1) 相邻对约占一半，与要求一致。

7.2　环节二：LRU 的两种实现方案对比

提示词：“用 C 实现 LRU，给出两种方案并比较代码量和复杂度。”

AI 给出两种：一是时间戳法，为每个页框记 last[]，命中即更新，置换时取最小值，约 15 行，查找 O(frames)；二是栈（双向链表）法，命中后把该页移到表头，淘汰表尾，约 50 行，淘汰 O(1) 但需手写链表指针。考虑到本实验 frames 最大只有 32，时间戳法的 O(32) 完全可接受，而链表法容易写出指针错误，因此选用时间戳法。这次对比让我意识到“数据结构选择要看问题规模”，不能只看渐进复杂度。

7.3　环节三：OPT 的优化尝试

提示词：“OPT 每次置换都向后扫描剩余页地址流，复杂度是多少，能否优化？”

AI 估算朴素实现为 O(N²·frames)；建议从后往前预处理每个位置的下一次出现位置（next[i]），置换时直接查表，把每次置换的比较降为 O(frames)，总体降到 O(N·frames)。我实现了两个版本并计时：320 条指令下两者都在 1 ms 以内，肉眼无法区分，而预处理版本多了一个 320 元素的辅助数组、代码可读性明显下降。因此报告中保留了朴素版本，只把“可用 next[] 预处理降低复杂度”作为优化思路记录在此。这件事的体会是：AI 给的优化在理论上正确，但是否采用要结合数据规模判断。

7.4　环节四：逻辑错误的检查

把写好的代码贴给 AI 复查，它指出三处问题：（1）LFU 在访问次数相同时未指定次序，淘汰结果依赖数组遍历顺序，同一组数据两次运行的结论可能不一致，建议增加 load[] 记录调入序号作为第二关键字；（2）NUR 的 while (ref[ptr] == 1) 在“所有页框访问位都为 1”时依赖循环内清零才能退出，如果漏写 ref[ptr] = 0 会死循环；（3）OPT 中“今后不再使用”的页面应赋予最大而不是最小的“下次使用位置”，否则会优先淘汰马上要用的页。这三处都是我自己调试时没意识到的，尤其是第（3）点，即使写反了程序也能跑出“看起来合理”的数字。

7.5　效果评价

（1）效率：五个算法的骨架若纯手写约需 2 小时，借助 AI 提示与代码片段后约 40 分钟完成，节省的主要是样板代码和查函数用法的时间；
（2）正确性：AI 找出的 3 处逻辑缺陷直接决定了结果是否可信，价值大于省下的时间；
（3）局限：AI 给出的 OPT 优化版可读性差，直接采用反而增加调试成本；此外它一度把公式中的“页地址流长度”理解成“不同页面的个数”，若照抄会把 320 写成 32，命中率算成 0，这类概念性错误必须人工核对；
（4）结论：AI 适合“给思路、做对比、查逻辑”，不适合“直接生成整份作业”。凡是涉及题目给定参数（320 条、1KB、10 条/页、32 页）的地方，都应以指导书为准并逐项对照。

八、错误与问题分析

（1）命中率恒为 100%。第一次运行时五种算法都输出 100%，排查后发现是漏写了 to_page()：page[] 是全局数组，未赋值时全部为 0，于是 320 次访问都被当成对第 0 页的访问，第一次调入之后全部命中。补上 page[i] = instr[i] / 10 后结果恢复正常。这个错误说明“指令地址”和“页号”是两个层次的概念，中间必须有一次地址变换；同时也提醒：全局数组默认清零会掩盖“忘记赋值”这类错误，用 -Wall 编译并检查输出是否“过于完美”是一个有效的自检手段。

（2）数组越界导致段错误。把内存容量试到 40 页时程序崩溃，因为 mem[MAXF]、last[MAXF] 等数组只开了 32 个元素。将循环上限限制在 32 页、并把 MAXF 定义为 32 后解决。

（3）FIFO 的 front 指针未取模。写成 front++ 后，跑到第 frames 次置换时下标越界。改为 front = (front + 1) % frames。

（4）OPT 逻辑写反。把“今后不再使用”的 next 初值设为 0，导致这类页面被当成“马上要用”而保留，命中率反而低于 FIFO。改为 next = N 后 OPT 恢复到最高水平，这也是判断 OPT 实现是否正确的一个简单自检：OPT 的命中率必须不低于其他任何算法。

（5）NUR 死循环。最初漏写 while 循环体里的 ref[ptr] = 0，当所有页框的访问位都是 1 时程序卡死，需要用 Ctrl+C 终止。补上清零语句后正常。

（6）结果每次运行不同。因为 srand((unsigned)time(NULL)) 用时间做种子，每次的指令流都不一样，命中率会有 1~2 个百分点的浮动。这属于正常现象，报告中的数据是同一次运行内五种算法的横向对比，具有可比性；若要严格复现，可改用 srand(1) 固定种子。

（7）编译警告。使用 -Wall 时若出现 “unused variable” 或 “comparison between signed and unsigned”，多是把循环变量类型写错或声明了未使用的中间变量，清理后编译完全干净。

九、实验总结

本次实验用 320 条带局部性的随机指令驱动五种页面置换算法，在 4~32 页的内存容量下测得了完整的命中率数据，主要收获有四点。

第一，把课本上“命中率＝1－失效次数/页地址流长度”这个公式真正算了一遍，才理解它衡量的是“访问能在内存中直接满足的比例”，而失效次数里既包含首次访问的强制性失效，也包含容量不足引起的置换失效。当 32 个页框装下全部 32 页时命中率恰好是 90%，剩下的 10% 全是强制性失效，这条上限是任何算法都无法突破的。

第二，实验数据验证了几条理论结论：OPT 始终最高，是理论下界（就失效次数而言）；LRU 与 NUR 接近且稳定，NUR 以极小的硬件代价换来了接近 LRU 的效果；FIFO 与 LRU 互有胜负，说明“先进先出”忽略访问历史是有代价的。同时也看到了理论之外的细节：LFU 在内存宽裕时反超 LRU，说明算法优劣与工作集规模、访问模式强相关，没有绝对最好的算法。

第三，对“实现细节决定结论”有了切身体会。同一套算法，OPT 把“不再使用”的优先级写反、LFU 平局不指定次序、NUR 忘写清零，程序都能跑出数字，但结论完全错误。判断实现是否正确需要自检手段：OPT 不应低于其他算法、32 页时应等于不同页面数对应的上限、LRU 的失效次数应随容量单调不增——这几条性质可以用来快速定位错误。

第四，对 AI 工具的使用有了更清楚的认识。它在澄清规则（50% 比例）、对比方案（LRU 两种实现）、查找逻辑缺陷上确实高效，但它对题目参数和概念细节并不可靠（把“页地址流长度”误解成“不同页面个数”），必须由人对照指导书逐项核对。合理的方式是把它当作“随时可问的同伴”，由自己判断取舍，而不是交给它生成整份作业。
